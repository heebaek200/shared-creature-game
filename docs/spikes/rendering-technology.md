## 그래픽 표현 기술 검증
관련 이슈 : [[기술검증] 크리처·아바타 브라우저 표현 방식 검증 (DOM/CSS vs Canvas) #6](https://github.com/heebaek200/shared-creature-game/issues/6)

1. 검증 목적
* 이 문서는 웹 기반 크리처 홈 화면 구현 시, 중앙의 공동 크리처와 주변의 "최대 20명 사용자 아바타" 를 원활하게 표현하고 상호작용하기 위한 최적의 브라우저 렌더링 기술을 검증하고 결정하기 위해 작성 됨

* 핵심 목적: 개발 난이도, 모바일 반응형 대응, 클릭 상호작용 및 레이어 합성의 용이성을 비교하여 가장 적합한 표현 방식을 채택
* 제외 범위: 정식 크리처 홈 화면 개발, WebSocket 실시간 접속·퇴장 처리, 실제 DB·API 연동, 복잡한 게임 물리 엔진이나 고급 애니메이션 구현


2. 검증 환경 및 방법
   * 검증 환경: Vanilla JavaScript 기반, DOM + CSS, Canvas 2D 
    **검증 방법**
       1. DOM + CSS, Canvas 2D를 이용해 프로토타입을 작성 후 동일한 조건에서 구동 검증
       2. 이미지 배치, 애니메이션 구현 난이도와 클릭 이벤트, 사용자 정보 표시 구현 난이도, 반응현 화면 대응과 유지보수성 비교


3. 검증 결과 (성공·실패 사례)
   * 검증 항목: DOM + CSS 방식 | Canvas 2D 방식
   
        **DOM + CSS 방식**
       - 성공: 각 아바타가 개별 DOM 요소로 존재하므로 CSS를 통한 배치, 반응형 대응, 클릭 이벤트 구현이 매우
         직관적이고 쉬움
       - 실패/한계: 20개 이상의 아바타가 동시에 복잡한 다중 애니메이션을 수행할 경우 DOM Reflow/Repaint로 인해 성능 저하 우려가 있으나 프로젝트의 단순한 정적 배치 및 미세한 움직임
         수준에서는 문제가 없음을 확인

        **Canvas 2D 방식**
       - 성공: 자유로운 좌표 관리와 Sprite 애니메이션 성능이 우수
       - 실패/한계: 캔버스 내부의 개별 아바타마다 마우스 좌표를 계산해 클릭 판정을 직접 구현해야 하고 HTML 반응형 레이아웃 연동이 DOM 방식보다 복잡하여 2주안에 완성하기에는 한계가 있다고 느낌

    
4. 최종 채택 기술 또는 방법과 판단 근거
   * 채택 기술: DOM + CSS 방식
   **판단 근거**
   - 약 2주라는 개발 기간내에 최대 20명의 아바타 배치, 클릭 시 아바타 정보 표시, 꾸미기 레이어 합성을 구현하기에는 DOM + CSS 방식이 더 좋다고 판단
   - 최대 20명 규모의 아바타 배치, 아이템 레이어 구조, 클릭 팝업 처리 등을 복잡한 알고리즘 없이 빠르게 처리 가능


5. 실제 구현 시 참고사항 
   **참고 사항**
    - 20명이 겹칠 때의 가독성을 위해 화면 중앙에 크리처를 두고 주변을 원형 또는 그리드 형태로 분산 배치
    - 아바타 선택 시 사용자 정보 표시
    - 성장 단계에 따라 크리처·아바타 바꾸기
