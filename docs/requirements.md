# 요구사항

> 기존 설계서의 절 번호·제목과 GitHub 앵커를 유지한 간결 버전입니다. 세부 수치·상태 전이는 [업무 규칙](business-rules.md), 요청·응답 계약은 [API 설계](api-design.md)를 참조합니다.

## 1. 의뢰인 배경

생활 습관 형성형 소셜 게임을 검증하려는 스타트업 기획자가 **4명, 약 2주 개발**을 전제로 웹 MVP 제작을 의뢰했습니다.

## 2. 프로젝트 목적

작은 일상 행동을 **일일·주간 퀘스트 → 개인 기여 → 그룹 크리처 성장**으로 연결하는 공동 육성 게임을 만듭니다. 느슨한 협력과 경쟁을 제공하며, 생활 습관 개선과 사회적 고립 감소는 검증 전 기대 효과입니다.

## 3. 대상 사용자

| 대상 | 사용 목적 |
|---|---|
| 생활 습관을 만들고 싶은 사람 | 작은 목표를 꾸준히 수행 |
| 공동 육성·경쟁을 즐기는 사람 | 그룹 크리처와 시즌 랭킹 참여 |
| 적극적 SNS 교류가 부담스러운 사람 | 채팅 없이 가볍게 협력 |
| 웹 브라우저 사용자 | 별도 앱 설치 없이 참여 |

가입 사용자는 친구 초대 여부와 관계없이 공개 그룹에 참여할 수 있습니다.

## 4. 필수 기능

### 4.1. 계정과 사용자

#### 구현할 기능

Google·Naver로 로그인하고 신규 사용자는 닉네임을 정해 가입합니다. 가입 후 그룹을 선택하거나 새 그룹을 만듭니다.

#### 주요 규칙

- 자체 이메일·비밀번호 인증은 제공하지 않습니다. 계정 식별은 `공급자 + 공급자 사용자 ID` 기준입니다.
- 신규 가입 시 이메일이 필요합니다. 같은 이메일의 다른 공급자 계정은 자동 연결하지 않습니다.
- OAuth 코드는 백엔드가 교환하고 로그인은 서버 세션으로 유지합니다. 공급자 토큰은 영구 저장하지 않습니다.
- 가입 대기 세션은 **30분**, 로그인 비활동 만료는 **7일**, 동시 세션은 **최대 3개**입니다.
- 역할은 `SUPER_ADMIN`, `PRIMARY`, `DEPUTY`, `MEMBER`로 구분합니다. 최초 `SUPER_ADMIN`은 환경변수의 공급자·사용자 ID가 일치하는 신규 가입자에게만 부여합니다.
- 네이버는 사전 검수 전 관리자·테스터 등록 계정으로만 시연합니다.

#### 작업 대상

`/login`, `/signup`, `/groups/select`, OAuth 콜백, 서버 세션, 사용자·소셜 계정·멤버십 데이터.

#### 처리 순서

1. 공급자 인증 및 서버 측 토큰·사용자 식별 검증.
2. 기존 계정이면 세션 발급, 신규 계정이면 가입 대기 문맥 생성.
3. 닉네임 제출 후 계정 생성 및 그룹 선택으로 이동.

#### 완료 확인

- 정상 로그인·가입·로그아웃 및 가입 대기 만료를 확인합니다.
- 이메일 미제공·중복 공급자 이메일·세션 불일치가 규칙에 맞게 차단됩니다.

### 4.2. 그룹과 공동 육성

#### 구현할 기능

사용자가 공개 그룹에 가입·탈퇴하거나 그룹을 생성하고, 그룹별 공동 크리처를 시즌 단위로 육성합니다.

#### 주요 규칙

- 활성 그룹은 사용자당 **1개**, 그룹 정원은 **20명**입니다. 자동 배정이나 가입 승인은 없습니다.
- 탈퇴·강퇴 후 **24시간** 동안 재가입을 제한하고 기존 기여·활동 기록은 보존합니다.
- 초대 링크는 기본적으로 만료·횟수 제한이 없으며 주 관리자 재발급 시 기존 링크를 무효화합니다. 링크는 자리를 선점하지 않습니다.
- 그룹당 주 관리자 1명, 부 관리자는 복수 지정 가능합니다. 강퇴 권한과 미접속 조건은 업무 규칙을 따릅니다.
- **4주 시즌**, 그룹 참여 후 **72시간 알 상태**, 미선택 시 무작위 부화. 그룹당 활성 크리처는 1마리입니다.
- 성장 단계는 `알 → 유년기 → 성장기 → 성숙기 → 완전체`. 경험치는 유효 퀘스트로만 얻습니다.

#### 작업 대상

`/groups/select`, `/group`, `/group-admin`, `/creature`, 그룹·멤버십·초대·시즌·크리처 데이터.

#### 처리 순서

1. 그룹 선택·생성 시 가입 자격과 정원을 검증합니다.
2. 그룹 멤버십과 현재 시즌의 알 상태 크리처를 확정합니다.
3. 부화·경험치 반영·시즌 종료를 서버 일정에 맞춰 처리합니다.

#### 완료 확인

- 정원 초과·중복 소속·재가입 제한이 발생하지 않습니다.
- 크리처 선택 기한과 시즌 종료 시점에 상태 및 기록이 정확히 반영됩니다.

### 4.3. 퀘스트와 보상

#### 구현할 기능

서버가 일일·주간 퀘스트를 배정하고 완료 여부를 검증하여 개인 기여도와 그룹 크리처 경험치를 지급합니다.

#### 주요 규칙

| 구분 | 일일 | 주간 |
|---|---:|---:|
| 배정 개수 | 3개 (하·중·상 각 1) | 7개 (하 3·중 2·상 2) |
| 갱신 시각 | 매일 00:00 KST | 월요일 00:00 KST |
| 퀘스트당 크리처 경험치 | 100 | 300 |
| 기여도 (하/중/상) | 10 / 20 / 30 | 30 / 60 / 90 |

- 검증 유형은 `SELF_CHECK`, `SERVER_EVENT`, `AGGREGATE`, `PHOTO_EXIF`이며 보상은 서버의 활성 배정 Snapshot을 기준으로 합니다.
- 사용자·퀘스트·기간별 보상은 **1회**만 확정합니다. 완료 후 취소하거나 다음 기간으로 이월하지 않습니다.
- 서비스 체크인은 사용자가 직접 수행하는 하루 1회 행동입니다. 오전 기상 체크인은 **05:00 이상~09:00 미만**입니다.
- 사진 퀘스트는 **JPEG 최대 10 MiB**, GPS·촬영 시각 EXIF 필수이며, 제출은 배정당 최대 5회·사용자당 분당 5회입니다.
- 위치 사진 인증은 Android Chrome과 iOS Safari 실기기 검증까지 포함한 **MVP 필수 기능**입니다. GPS가 없는 사진의 예외 승인은 없습니다.
- 동시 완료 시 보상·기여도·크리처 경험치가 중복·유실되지 않아야 합니다.

#### 작업 대상

`/quests`, 체크인·사진 제출, 퀘스트 템플릿·배정·완료·활동·보상·기여도 데이터.

#### 처리 순서

1. 서버가 기간별 템플릿을 순회 배정합니다.
2. 수행 증빙을 유형별로 판정하고 기간·소속·중복 완료를 재검사합니다.
3. 하나의 트랜잭션으로 완료·보상·점수·성장을 확정합니다.

#### 완료 확인

- 일일·주간 퀘스트와 각 검증 유형이 실제 조건대로 동작합니다.
- 중복·동시 요청과 잘못된 사진에 중복 보상이 지급되지 않습니다.

### 4.4. 실시간 기능

#### 구현할 기능

공동 크리처 성장·기여도·그룹 상태와 접속 중인 그룹원 아바타를 실시간 갱신합니다.

#### 주요 규칙

- **DB Commit 결과가 유일한 확정 상태**이며 WebSocket은 결과 전달용입니다.
- 인증된 현재 그룹 사용자만 구독할 수 있고 클라이언트의 임의 `SEND`는 허용하지 않습니다.
- 아바타는 최대 20명까지 노출하고 접속·퇴장·장착 변경만 전파합니다. 이동 좌표 스트리밍·채팅은 제외합니다.
- Presence는 MVP 단일 서버 메모리에 두고 영구 접속 이력을 저장하지 않습니다.

#### 작업 대상

`/creature`, 그룹 전용 STOMP 구독, 아바타 장착 상태·Presence·Snapshot 재조회.

#### 처리 순서

1. REST로 초기 Snapshot을 조회합니다.
2. 검증된 세션으로 그룹 채널을 구독합니다.
3. 확정 이벤트를 반영하고 연결 재수립 시 Snapshot으로 재동기화합니다.

#### 완료 확인

- 다른 그룹 구독과 임의 메시지 송신이 거부됩니다.
- 둘 이상의 브라우저에서 확정 상태가 일관되게 보입니다.

### 4.5. 결제와 환불

#### 구현할 기능

아바타 꾸미기 아이템을 포트원 V2 카카오페이 테스트 결제로 구매하고, 미사용 아이템의 환불을 관리자가 처리합니다.

#### 주요 규칙

- 한 결제에 아이템 **1개**만 구매합니다. 실제 금전 거래는 범위 밖입니다.
- 아이템은 최초 장착 시 사용 처리되며 이후 해제해도 미사용으로 돌아가지 않습니다.
- 미사용 아이템만 환불 가능하며, 전체 관리자가 요청을 승인·거절합니다.
- 결제 성공과 취소 성공은 **브라우저 응답이 아닌 PG 서버 조회·Webhook 검증 결과**로 확정합니다.
- PG 취소 결과가 불명확하면 `CANCEL_UNKNOWN`을 유지하고 확인 전 아이템을 회수하거나 중복 취소하지 않습니다.
- 장착과 환불 승인, 결제 중복 처리에는 잠금·멱등 처리를 적용합니다.

#### 작업 대상

`/shop`, `/avatar`, `/payments`, `/admin/refunds`, 구매·결제 거래·보유 아이템·환불 요청 데이터.

#### 처리 순서

1. 서버가 주문을 발급하고 브라우저가 테스트 결제창을 호출합니다.
2. 서버가 PG 상태·금액·통화를 조회해 구매 및 아이템 지급을 확정합니다.
3. 환불 요청 → 관리자 판단 → PG 취소 확인 → 아이템 회수 순으로 처리합니다.

#### 완료 확인

- 유효 결제만 아이템을 지급하고 같은 결제는 중복 지급되지 않습니다.
- 미사용 환불만 완료되며 결과 미확정·장착 경합 시 정합성이 유지됩니다.

### 4.6. 관리자와 사용자 환경

#### 구현할 기능

전체 관리자는 서비스 지표·회원·그룹·퀘스트·결제·환불·신고·운영 경고를 조회하고, 사용자는 반응형 화면과 다크 모드를 이용합니다.

#### 주요 규칙

- 전체 관리자 전용 기능과 그룹 관리자 기능을 분리합니다.
- 대시보드는 서버 집계 결과를 사용합니다. 운영 경고는 미해결 원본 상태를 기반으로 표시합니다.
- 데스크톱은 사이드바, 모바일은 하단 5개 내비게이션을 사용합니다.
- 라이트 테마 기본색은 `#16836F`·`#A8DBC1`·`#FFD17B`·`#F3FAF6`입니다.

#### 작업 대상

`/admin`, `/admin/reports`, `/admin/refunds`, `/admin/operations`, 공통 레이아웃·테마 설정.

#### 완료 확인

- 역할별 관리자 접근 제한, 주요 통계와 상태 확인, 라이트·다크 모드 전환을 확인합니다.

## 5. 우선순위와 조건부 범위

**전부 MVP 필수 범위:** 소셜 로그인, 공개 그룹, 공동 육성·아바타, 퀘스트·보상, 개인·그룹 랭킹, WebSocket, 동시성, PG 테스트 결제·환불, 관리자 대시보드, 다크 모드, **EXIF 사진 인증**, Gemini 그룹 소개 교정.

EXIF는 실제 Android Chrome·iOS Safari에서 촬영·업로드 및 실패 처리를 검증해야 합니다. 기술 검증 실패 시 기능을 제외하지 않고 MVP 미완료로 판단합니다.

## 6. 범위 밖 기능

- 실제 광고·광고 보상·광고 제거 상품, 유료 성장 가속, 실제 운영 결제.
- GPS 없는 사진의 대체 인증, 정밀 위치 추적, 복잡한 부정행위 탐지.
- 네이티브 앱, 복잡한 친구·팔로우·메시지 기능.

## 7. 개발 제약

| 항목 | 확정 기준 |
|---|---|
| 프로젝트 | `다 같이 키우는 생명체` / 저장소 `shared-creature-game` |
| 개발 인원·기간 | 4명·약 2주 |
| 백엔드 | Java 21, Spring Boot, MySQL |
| 프론트엔드 | Vanilla JavaScript ES Module, Vite, Bootstrap v5, Full CSR |
| Java 좌표 | Group `com.team`, Artifact `shared-creature-game`, Package `com.team.sharedcreature` |
| 데이터베이스 | 업무 테이블 40개 (`photo_submissions` 포함), 인프라 테이블 별도 |
| 시각 | DB UTC `DATETIME(6)`, 업무 경계 `Asia/Seoul` |
| 개발·통합 환경 | localhost HTTP / 모바일·OAuth·PG 검증에는 임시 HTTPS 터널 |
| 로그인 시도 | 10분 유효, 종료 후 24시간에 시도 이력 삭제 |
| 호출 제한 | OAuth 세션당 10분 5회·IP당 10분 30회; Gemini 분당 5회·일 30회·동시 2회 |
| 데이터 보존 | 거래·활동 이력 유지, Scheduler 성공 90일·실패/감사 로그 1년 |
| 무결성 | 활성 멤버십·주 관리자·환불·초대는 UNIQUE, 핵심 이력 FK는 삭제 제한 |

그룹 소개 Gemini 교정은 **한국어 최대 500자**, 제안 적용은 사용자가 결정합니다. 별도 사용자 알림 테이블은 만들지 않습니다. 구현 중 계약에 없는 필드·상태·API는 임의로 추가하지 않습니다.

## 8. MVP 완료 기준

| 검증 영역 | 완료 확인 |
|---|---|
| 인증·보안 | Google/Naver 로그인, 가입, 세션 분리, 타인 자원 접근·WebSocket 임의 송신 차단 |
| 공동 육성 | 그룹 가입·정원·강퇴·시즌·부화·성장 정상 동작 |
