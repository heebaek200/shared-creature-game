# 화면 설계서

## 1. 공통 방향

- 프론트엔드는 Full CSR이며 브라우저 새로고침 시에도 같은 URL 화면을 복원합니다.
- 화면은 Vanilla JavaScript ES Module로 구성하고 Bootstrap v5의 Grid·Utility·접근 가능한 UI Component를 기본으로 사용합니다.
- 기본 History API Router와 Route Guard의 실제 구현은 스피어 프로토콜의 공통 기반 구현 범위에 포함합니다.
- 화면 접근 판단은 최초 부트스트랩에서 조회한 `/api/v1/me`의 계정·온보딩·그룹·권한 상태를 기준으로 합니다.
- 프론트엔드 Route Guard는 올바른 화면으로 안내하는 역할만 하며 실제 권한과 업무 조건은 모든 API에서 서버가 다시 검증합니다.

로그인한 그룹 회원의 기본 경로는 `/creature`, 전체 관리자의 관리 기본 경로는 `/admin`입니다. 전체 관리자 권한은 그룹 멤버십 역할과 별개이며 여러 그룹을 관리할 수 있습니다.

`REQ-UI-001`, `REQ-UI-002`는 모든 화면에 공통 적용합니다. `REQ-AUTH-004`는 Route Guard 전체, `REQ-RT-001`은 크리처 홈과 공통 헤더의 실시간 상태 표시에서 확인합니다. 요청 ID의 원문 시나리오와 성공 결과는 [사용자 시나리오 및 업무 규칙](business-rules.md#0-요청-식별-번호와-추적-기준)을 기준으로 합니다.

화면을 구현할 때 사용할 초기 조회·버튼 동작 Operation ID와 성공 후 처리는 [구현 시작 안내서의 화면별 REST API 연결표](implementation-guide.md#4-화면별-rest-api-연결표)를 따릅니다. 각 Operation의 Method·Path·필드·오류는 [REST API 설계서](api-design.md)가 최종 기준입니다.

## 3. Route Guard와 기본 이동

1. 비로그인 사용자가 보호 경로에 접근하면 안전하게 검증된 내부 `returnUrl`을 유지하고 `/login`으로 이동합니다.
2. 소셜 인증을 마쳤지만 계정 생성이 끝나지 않은 사용자는 `/signup`으로 이동합니다.
3. 일반 계정 생성 후 활성 그룹이 없으면 `/groups/select`로 이동합니다.
4. 탈퇴·강퇴 후 24시간 제한 중에도 `/groups/select`는 표시하지만 가입·생성 동작을 비활성화하고 서버 시각 기준 제한 종료 시각과 남은 시간을 표시합니다.
5. 활성 그룹이 있는 일반 사용자가 로그인·가입 전용 화면에 접근하면 `/creature`로 이동합니다.
6. `/group-admin`은 현재 그룹의 `PRIMARY` 또는 `DEPUTY`, `/admin/**`는 `SUPER_ADMIN`만 접근할 수 있습니다.
7. 인증됐지만 역할이 부족하면 `/403`, 매칭되지 않는 경로는 404 화면을 표시합니다.

Route Guard는 `/api/v1/me`의 조합을 고정 매핑합니다. `ANONYMOUS + NOT_STARTED`는 `/login`, `SIGNUP_PENDING + SIGNUP_REQUIRED`는 `/signup`, `AUTHENTICATED + GROUP_REQUIRED`는 `/groups/select`, `AUTHENTICATED + COMPLETED`는 역할별 기본 화면으로 이동합니다.

`returnUrl`은 같은 Origin의 사전 정의된 CSR 경로만 허용해 외부 Redirect에 사용하지 않습니다. 초대 토큰과 OAuth 진행 문맥은 `localStorage`나 URL Query로 복제하지 않고 서버 측 임시 상태에서 유지합니다.

서비스 공개 시각은 첫 시즌 시작 월요일 0시와 같으므로 프리시즌 전용 화면이나 시즌 없는 사용자 Route는 만들지 않습니다.

## 4. 소셜 로그인·회원가입과 그룹 선택

- 로그인·회원가입 시작 화면에는 구글 로그인과 네이버 로그인만 제공합니다.
- 이메일·비밀번호 입력 화면은 제공하지 않습니다.
- 소셜 로그인이 최초 가입으로 처리되면 별도의 그룹 선택 페이지로 이동합니다.
- 그룹 선택 페이지는 신규 가입자와 탈퇴·강퇴 후 24시간 가입 제한이 끝난 사용자가 공통으로 사용합니다.
- 그룹 선택 페이지에서 기존 공개 그룹 가입 또는 새 그룹 생성을 선택할 수 있습니다.
- 새 그룹을 생성한 사용자는 주 관리자가 됩니다.
- 초대 링크에서 수락하면 링크 정보를 서버의 OAuth 시도 상태에 연결한 채 소셜 로그인·회원가입 화면으로 이동합니다.
- 초대 링크에서 거절하면 링크 정보를 버리고 일반 소셜 로그인·회원가입 화면으로 이동합니다.
- OAuth 콜백은 신규 사용자의 검증된 소셜 정보와 초대 문맥만 가입 대기 세션에 저장하고 계정은 생성하지 않습니다. 가입 대기 세션은 콜백 완료 후 30분 동안만 유효합니다.
- 회원가입 페이지 진입 또는 제출 시 가입 대기 세션이 만료됐으면 계정을 만들지 않고 만료 안내를 표시한 뒤 로그인 페이지로 이동해 소셜 인증을 다시 시작하게 합니다.
- `/signup`에서 닉네임을 제출할 때 계정 생성 직전에 링크와 그룹 가입 조건을 다시 검사합니다.
- 그룹 가입 조건 검사가 실패해도 계정은 유지하며 실패 이유를 표시한 뒤 그룹 선택 페이지로 이동합니다.
- 기존 가입자가 링크를 수락하면 새 회원가입을 진행하지 않습니다. 그룹이 없고 가입 조건을 충족하면 초대 그룹에 즉시 가입해 크리처 홈으로 이동하고, 실패하면 그룹 없는 상태에서 이유와 그룹 선택 이동을 표시합니다.
- 동일 이메일로 다른 공급자 계정이 이미 존재하면 자동 연결하지 않고 기존 가입 공급자를 표시해 해당 방식으로 다시 로그인하도록 안내합니다.
- 신규 가입 중 이메일 제공 동의를 거부했거나 이메일을 제공받지 못하면 가입을 중단하고 이메일 동의가 필요하다는 안내와 다시 로그인 버튼을 표시합니다.
- 네 번째 기기 또는 브라우저에서 로그인하면 가장 오래된 기존 세션이 종료되었다는 안내를 로그인 완료 화면에 표시합니다.
- OAuth Callback이 로그인 시작 브라우저와 다르면 로그인 화면에 세션이 일치하지 않아 다시 시작해야 한다는 안내를 표시합니다. Callback URL이나 `state`를 다시 사용하지 않습니다.

## 5. 관리자 대시보드

- 관리자 대시보드의 통계 시각화에는 Google Charts JavaScript 라이브러리를 사용합니다.
- 요약 카드에는 오늘 활동 사용자 수, 활성 그룹 수와 평균 정원 사용률, 현재 시즌 퀘스트 완료율, 테스트 결제 금액, 환불 대기, 미처리 신고와 운영 경고 건수를 표시합니다.
- 최근 14일 활동 사용자·퀘스트 완료 추이는 Line Chart, 현재 시즌 성장 단계 분포는 Column Chart, 그룹 점수 상위 10개는 Bar Chart로 표시합니다.
- 최근 30일 결제·환불 추이는 Combo Chart, 그룹 정원 사용률 분포는 Donut Chart로 표시합니다.
- 기간은 KST 기준 7일·30일·현재 시즌, 그룹은 전체·특정 그룹으로 필터링합니다.
- 브라우저가 원본 행을 재집계하지 않고 백엔드가 권한 검증을 거친 집계 결과만 반환합니다.
- 진입 즉시 조회하고 Browser Tab이 보이는 동안 60초마다 갱신하며 수동 새로고침과 마지막 집계 시각을 제공합니다. 비활성 Tab에서는 자동 갱신을 중단합니다.
- 차트마다 동일 정보를 확인할 수 있는 수치 또는 표를 제공하고 Google Charts 로드 실패 시에도 요약 카드와 표는 유지합니다.
- 하단에는 미처리 신고, 환불 대기와 운영 경고의 최근 항목을 표시하고 각 전용 관리 화면으로 연결합니다.
- 운영 경고 화면은 현재 미해결 항목만 보여주고 해결 상태 Filter나 과거 해결 이력 탭은 제공하지 않습니다.

## 6. 공통 레이아웃과 반응형 내비게이션

- 데스크톱은 좌측 사이드바, 상단 헤더와 본문 영역으로 구성합니다.
- 모바일은 상단 헤더와 `크리처`, `퀘스트`, `랭킹`, `그룹`, `더보기`의 하단 5개 내비게이션을 사용합니다.
- 상점, 아바타와 결제 내역은 `더보기`에서 접근합니다.
- `PRIMARY`, `DEPUTY`에게만 그룹 관리 메뉴를 표시하고 전체 관리자 화면은 일반 화면과 분리된 관리자 전용 사이드바를 사용합니다.
- 헤더에는 현재 그룹, 시즌 남은 기간, 프로필 바로 앞의 실시간 연결 상태와 테마 전환 버튼을 표시합니다.
- 관리자 차트는 좁은 화면에서 한 열로 배치하고 표 영역은 가로 스크롤 또는 요약 카드로 전환합니다.

## 7. 색상과 다크 모드

서비스의 시각 방향은 자연, 성장과 편안함입니다. 크리처의 성장·건강·돌봄 시스템에 어울리는 부드러운 녹색 계열을 사용합니다.

| 토큰 | 색상 | 용도 |
|---|---|---|
| `--color-primary` | `#16836F` | 주요 버튼, 활성 메뉴, 성장 상태 |
| `--color-secondary` | `#A8DBC1` | 보조 영역, 진행 배경, 선택 상태 |
| `--color-accent` | `#FFD17B` | 보상, 주의 환기, 핵심 강조 |

| `--color-surface` | `#FFFFFF` | 카드와 패널 |

- 테마 선택은 `시스템 설정`, `라이트`, `다크` 세 가지이며 최초 기본값은 시스템 설정입니다.
- 선택값은 `localStorage`에 저장하고 앱 본문 렌더링 전에 `data-theme`을 적용해 색상 깜빡임을 줄입니다.
- Google Charts는 현재 CSS Theme Token에서 색을 읽어 테마 변경 시 다시 그리고, 창 크기 변경은 Debounce 후 반영합니다.
- 상태는 색상만으로 표현하지 않고 문구와 아이콘을 함께 사용합니다.
- 키보드 포커스 표시, 일반 텍스트 4.5:1 이상의 명암과 `prefers-reduced-motion`을 지원합니다.

## 8. 크리처 홈

- 크리처 이미지, 이름, 현재 성장 단계와 시즌 상태를 그룹 정원 공간의 중심에 표시합니다.
- 현재 접속한 그룹 구성원의 아바타를 공동 크리처 주변에 최대 20명까지 배치하고 장착 아이템 외형을 적용합니다.
- 아바타는 사용자 ID 기반의 안정적인 이동 구역 안에서 자동으로 걷고 멈추며 서로 겹치거나 크리처 핵심 정보를 가리지 않게 합니다.
- 자신의 아바타는 강조선과 `나`로 구분하고, 모바일에서는 선택하지 않은 다른 아바타의 이름표를 숨깁니다.
- 다른 아바타를 선택하면 닉네임, 시즌 기여도·그룹 내 순위와 장착 아이템을 Drawer 또는 Popover로 표시합니다. 판매 중인 아이템에는 `상점에서 보기` 동작을 제공합니다.
- 누적 경험치, 다음 단계 기준과 진행률을 함께 표시하고 완전체 이후에는 누적 경험치만 계속 증가시킵니다.
- 알 기간에는 부화까지, 부화 이후에는 시즌 종료까지의 서버 기준 남은 시간을 표시합니다.
- 오늘 그룹이 획득한 경험치와 최근 기여 활동을 표시하고 WebSocket 이벤트가 Commit된 뒤 갱신합니다.
- 현재 사용자가 수행할 퀘스트가 있으면 퀘스트 화면으로 이동하는 주 행동 버튼을 제공합니다.
- `prefers-reduced-motion`에서는 산책 애니메이션을 멈추고 같은 정보를 정적인 배치로 제공합니다.
- WebSocket 재연결 중에는 마지막 Snapshot을 흐리게 유지하고 재연결 후 REST Snapshot으로 접속자와 장착 상태를 교정합니다.

## 9. 퀘스트 화면

- 일일·주간 탭에 배정된 퀘스트의 난이도, 경험치, 기여도, 검증 방식과 기간을 표시합니다.
- 퀘스트 상태는 `진행 가능`, `처리 중`, `완료`, `기간 종료` 문구와 아이콘으로 구분합니다.
- 완료 요청 중에는 같은 버튼의 중복 제출을 막고 중복 요청 응답이 기존 완료라면 완료 상태로 동기화합니다.
- `PHOTO_EXIF` 배정에는 사진 선택, 업로드 진행, GPS·촬영 시각 누락과 판정 실패 이유를 표시하는 필수 UI를 제공합니다.
- 사진 선택은 JPEG·최대 10 MiB 안내와 `accept=image/jpeg` Hint를 제공하되 서버 검사를 최종 기준으로 합니다. iPhone 시연에는 카메라 포맷을 `높은 호환성`으로 설정해야 한다는 도움말을 표시합니다.
- HEIC·HEIF를 선택하면 자동 변환하지 않고 JPEG로 다시 촬영하거나 내보내도록 안내합니다.
- 화면 문구는 `야외 활동 증명`처럼 단정하지 않고 `GPS·촬영 시각 확인`으로 표시하며, 서버가 실외 여부나 실제 이동을 검증하지 않는다는 한계를 안내합니다.

## 10. 랭킹과 그룹 화면

- 랭킹은 그룹 내 개인 랭킹과 전체 그룹 랭킹 탭으로 구분하고 현재 사용자·그룹의 순위를 상단에 고정 요약합니다.
- 동점은 점수 도달 시각, ID 순으로 정렬한다는 기준을 도움말로 제공합니다.
- 탈퇴 회원은 진행 중 시즌 개인 랭킹에 `탈퇴` Badge로 표시하되 현재 구성원 목록에서는 제외합니다.
- 그룹 화면에는 그룹명, 현재 인원과 정원 20명, 주·부 관리자와 역할 Badge를 포함한 현재 구성원 목록을 표시합니다.
- 일반 사용자에게 자진 탈퇴 동작을 제공하고 `PRIMARY`, `DEPUTY`에게 그룹 관리 화면 이동 버튼을 표시합니다.
- 유일한 구성원인 주 관리자가 탈퇴를 누르면 같은 확인 Modal에서 그룹·초대 링크·현재 시즌 참여도 함께 종료되며 기록은 보존된다는 내용을 표시합니다. 별도 해산 화면은 만들지 않습니다.
- 본인을 제외한 같은 그룹 구성원에게 신고 동작을 제공하고 신고 Modal에서 분류와 10~1000자 내용을 입력받습니다. 신고 접수 자체로 즉시 강퇴하지 않으며 전체 관리자가 검토합니다.

## 11. 공통 조회·작업 상태

- 최초 조회는 실제 화면 구조와 비슷한 Skeleton을 사용해 Layout Shift를 줄입니다.
- 데이터가 없으면 빈 화면만 두지 않고 원인과 가능한 다음 행동을 함께 표시합니다.
- 조회 실패는 사용자용 오류 문구, 추적 가능한 오류 코드와 다시 시도 버튼을 표시합니다.
- `429 RATE_LIMIT_EXCEEDED`이면 서버의 `Retry-After`까지 버튼을 비활성화하고 남은 시간을 표시합니다. Gemini·사진 처리 포화 또는 Timeout은 입력과 선택한 파일을 가능한 범위에서 유지하고 사용자가 직접 다시 시도하게 합니다.
- WebSocket 연결 상태는 헤더의 프로필 바로 앞에 `실시간 연결됨`, `재연결 중`, `30초 동기화 중`으로 표시하고 재연결 후 관련 REST API를 다시 조회합니다.
- 성공·실패 Toast는 현재 작업 결과를 잠시 안내하는 UI Feedback으로만 사용하며 프로젝트 이후 기능인 영속 알림으로 저장하지 않습니다.
- 결제, 탈퇴, 강퇴와 권한 변경은 영향과 되돌릴 수 있는지를 설명하는 확인 Modal을 사용합니다.
- 변경 가능한 서버 상태는 Modal을 연 시점이 아니라 최종 제출 시점에 다시 검증합니다.

## 12. 그룹 관리 화면

- 구성원 목록에는 역할과 마지막 인증 활동 시각을 표시하고 현재 관리자가 실행할 수 있는 작업만 노출합니다.
- 주 관리자는 일반 회원에게 부 관리자 권한을 부여하고 부 관리자 권한을 회수할 수 있습니다.
- 주 관리자는 마지막 인증 활동 후 72시간이 지난 일반·부 관리자 회원을 강퇴할 수 있고, 부 관리자 권한 회수는 활동 시각과 관계없이 할 수 있습니다.
- 부 관리자는 마지막 인증 활동 후 72시간이 지난 일반 회원만 강퇴할 수 있으며 주 관리자와 다른 부 관리자를 대상으로 할 수 없습니다.
- 주 관리자만 초대 링크를 재발급할 수 있고 기존 링크가 즉시 무효화된다는 점을 확인 Modal에 표시합니다.
- 초대 Token 원문은 저장하지 않으므로 그룹 생성·재발급 성공 직후에만 복사할 수 있습니다. 활성 링크 원문을 잃은 경우 기존 링크를 즉시 무효화하고 새 링크를 발급받도록 안내합니다.
- 주·부 관리자는 부화 기한 전까지 크리처를 선택·변경할 수 있습니다.
- 시즌 중 생성한 그룹도 즉시 현재 시즌의 알을 시작하며, 화면에는 그룹 생성 시각부터 72시간인 부화 기한을 표시합니다.
- 크리처 선택 탭은 `GET /api/v1/creature-species`의 활성 종을 표시 순서대로 보여주고 선택 저장 시 종 ID만 전송합니다.
- 활성 구성원이 2명 이상이면 주 관리자는 다른 활성 회원에게 권한을 이전하기 전에는 자진 탈퇴할 수 없습니다. 유일한 구성원이면 탈퇴와 그룹 비활성화를 함께 확인합니다.
- 이전 확인 Modal은 대상이 새 주 관리자가 되고 현재 주 관리자는 일반 회원으로 변경된다는 점을 표시합니다. 성공 후 현재 사용자의 그룹 관리 권한을 즉시 다시 계산합니다.
- 강퇴 Modal에는 대상, 사유와 강퇴 후 24시간 가입 제한을 표시하며 권한·역할·마지막 인증 활동 조건은 제출 시 서버가 다시 검사합니다.

## 13. 상점·아바타·결제·환불 화면

- 상점의 결제 동작은 `카카오페이 테스트 결제` 하나만 제공하며 다른 결제수단 선택 UI는 표시하지 않습니다.
- PC에서는 카카오페이 결제창을 IFrame으로 열고 모바일에서는 Redirect 후 결제 복귀 경로로 돌아옵니다.

- 상품 카드에는 슬롯, 가격, 보유 여부와 판매 상태를 표시하고 결제 진행 중에는 중복 구매 동작을 막습니다.
- PG 결과가 불명확하면 성공·실패로 단정하지 않고 `확인 중`으로 표시합니다.
- 아이템을 최초 장착하기 전에 사용 처리 후 환불할 수 없다는 내용을 확인하고, 장착을 해제해도 최초 사용 시각은 유지됩니다.
- 주문, 결제, 아이템 사용과 환불 상태는 결제 내역의 Timeline으로 표시합니다.
- 결제 성공, 미사용 아이템, 진행 중 환불 없음 조건을 모두 만족할 때만 사유를 입력해 환불을 요청할 수 있습니다.
- 전체 관리자는 환불 요청을 승인·거절할 수 있고 PG 취소 처리 중에는 재승인 동작을 막습니다.
- `CANCEL_UNKNOWN`은 `PG 결과 확인 중`으로 표시하고 조회·정합성 복구 대상으로 연결합니다.
- 환불 완료로 회수된 아이템은 장착하거나 다시 선택할 수 없으며 사용자 메시지는 내부 예외 대신 이해 가능한 실패 이유를 사용합니다.

## 14. 가입·초대·그룹 선택 입력과 Feedback

- 회원가입 화면은 소셜 공급자와 이메일을 읽기 전용으로 표시하고 서비스 닉네임만 입력받습니다.
- 닉네임은 NFKC 정규화와 양끝 공백 제거 후 2~20자로 검사합니다. 입력 완료 후 중복 여부를 확인할 수 있지만 제출 시 서버가 최종 재검사합니다.
- 초대 화면은 그룹명, 현재 인원과 정원, 수락·거절 동작을 표시합니다. 무효화된 링크에는 이유와 일반 가입 이동 동작을 제공합니다.
- 초대 수락 이후에도 가입 제출 시 링크 유효성, 정원, 기존 소속과 24시간 제한을 다시 검사합니다.
- 그룹 선택 목록은 그룹명, 현재 인원과 남은 자리를 표시하고 정원 마감 그룹의 가입 버튼을 비활성화합니다.
- 그룹명 검색과 페이지 단위 조회를 제공하며 새 그룹 이름은 NFKC 정규화와 공백 제거 후 2~30자·전역 중복을 검사합니다.
- 새 그룹 소개는 선택 입력 500자이며 `AI 문장 다듬기`를 누른 경우에만 Gemini 교정을 요청합니다. 결과는 원문과 나란히 보여주고 사용자가 적용하기 전에는 입력값을 바꾸지 않습니다.
- Gemini 요청이 실패하면 원문을 유지하고 교정 없이 그룹을 생성할 수 있게 안내합니다.
- 24시간 가입 제한 중에는 서버 기준 종료 시각과 남은 시간을 표시하고, 종료 시 서버 상태를 다시 조회한 뒤 가입·생성 동작을 활성화합니다.
- 제출 중에는 같은 버튼을 비활성화하고 `정원 마감`, `이미 그룹 소속`, `재가입 제한`, `이름 중복`, `링크 무효`처럼 다음 행동을 판단할 수 있는 업무 사유를 표시합니다.
