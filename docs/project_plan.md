# 다 같이 키우는 생명체

> 팀 프로젝트 통합 기획서 **v0.2** · 2026-11-02 기획 합의 반영  
> **서비스명:** 다 같이 키우는 생명체
> **서비스 유형:** 공동 육성 게임
> **개발 조건:** 4명 · 약 2주 · Java 21 LTS · Spring Boot · MySQL · 웹 브라우저 중심
> **문서 단계:** 서비스 기획 / MVP 범위 정의 (상세 설계 이전)

## 1. 프로젝트 개요

**한 줄 소개:** 누구나 참여할 수 있는 그룹에서 일상 퀘스트와 야외 미션을 수행하고, 공동 크리처를 성장시키며 개인·그룹 간에 경쟁하는 웹 기반 소셜 육성 서비스.

가입한 사용자는 그룹에 참여해 일일·주간 퀘스트를 수행한다. 퀘스트 성과는 크리처의 성장과 개인 기여도에 반영되며, 그룹 내 개인 랭킹 및 그룹 간 랭킹을 통해 협력과 경쟁의 동기를 함께 제공한다.

게임에서 다루는 대상을 **크리처(육성 대상)**와 **아바타(사용자 꾸미기 대상)**로 분리한다. 크리처의 육성·성장은 게임 플레이의 요소이며, 결제 기능은 아바타를 꾸미는 상품에 연결한다. 기본 서비스는 별도의 모바일 앱 설치 없이 웹 브라우저로 접근할 수 있도록 기획한다.

## 2. 기획 배경과 해결하려는 문제

- **일상 활동의 동기 부족:** 실내에서 즐기는 활동이 많아지면서 일부 사용자는 가벼운 외출이나 규칙적인 생활을 시작할 계기를 얻기 어렵다.
- **사회적 교류의 진입 장벽:** 새로운 사람들과 대화를 시작하거나 적극적인 SNS 활동을 이어가는 것을 부담스럽게 느낄 수 있다.
- **활동 지속의 어려움:** 산책·기상 습관처럼 작지만 꾸준한 활동은 혼자 지속할 동기가 약할 수 있다.

**해결 방향:** 가벼운 퀘스트를 게임의 성장·경쟁 요소에 연결하고, 낯선 사용자와도 하나의 목표를 공유하며 느슨하게 협력할 수 있는 참여 경험을 제공한다. 개인의 활동은 크리처 육성에, 여러 사람의 활동은 그룹 성과에 반영한다.

> 사회적 고립 감소, 야외 활동 증가, 생활 습관 개선은 서비스가 지향하는 **가설적 기대 효과**이며, 현재 검증된 결과로 제시하지 않는다.

## 3. 주요 사용자와 서비스 콘셉트

- **주요 대상:** 작은 일상 활동에 동기가 필요한 사람, 가벼운 게임을 즐기는 사람, 다른 사용자와 공동 목표를 공유하고 싶은 사람.
- **참여 범위:** **가입 사용자 전체**를 대상으로 한다. 친구·지인 초대에 제한되는 프라이빗 서비스로 기획하지 않는다.
- **그룹:** 공개적인 참여를 전제로 여러 사용자가 소속되고, 그룹 단위의 크리처 육성 및 경쟁이 이루어진다.
- **크리처:** 퀘스트 성과로 성장·진화하는 **육성 요소**. 유료 구매를 성장 조건에 포함하지 않는다.
- **아바타:** 사용자에게 연결되는 **꾸미기 요소**. 외형을 바꾸는 상품을 테스트 결제 대상으로 삼는다.
- **경쟁:** **그룹 내 개인 기여도**와 **그룹 간 경쟁**을 모두 제공한다.
- **게임 표현:** 웹 기반 이미지·간단한 애니메이션으로 성장과 꾸미기 결과를 표현한다.

**육성 단위:** 그룹마다 시즌별 활성 공동 크리처 1마리를 육성하며 개인별 크리처는 MVP에 포함하지 않는다. 크리처는 공동 육성, 사용자 아바타는 꾸미기 과금 역할을 담당한다.

**참여 방식:** 그룹 없는 사용자가 정원이 남은 공개 그룹을 직접 선택해 승인 없이 가입하거나 새 그룹을 생성한다. 자동 매칭과 추천 배정은 제공하지 않는다.

## 4. 핵심 이용 흐름

1. 사용자가 구글 또는 네이버 소셜 로그인으로 가입한다.
2. 가입 사용자가 정원이 남은 공개 그룹을 선택해 가입하거나 새 그룹을 생성한다.
3. 그룹의 크리처와 본인의 아바타, 오늘의 퀘스트를 확인한다.
4. 일일·주간 퀘스트를 수행하고 결과를 제출한다.
5. 서버가 퀘스트 조건을 검사해 보상을 지급하고, 개인 기여도와 그룹 성장 상태를 갱신한다.
6. 관련 사용자에게 성장 및 기여도 변화가 실시간 반영된다.
7. 개인·그룹 랭킹을 통해 경쟁 결과를 확인한다.
8. 원하는 사용자는 **아바타 꾸미기 아이템**을 PG 테스트 결제로 구매한다. 사용 여부에 따라 환불 가능 여부를 판정한다.

## 6. 퀘스트 시스템과 야외 사진 인증

### 6.1 퀘스트 구성

야외 활동은 **여러 일일·주간 퀘스트 중 하나**이며, 크리처를 성장시키기 위한 유일한 경로가 아니다.

| 분류 | 퀘스트 예시 | 판정 개념 |
|---|---|---|
| 일일 | **기상 미션** | 지정 시간 조건 내 웹 체크인 |
| 일일 | 오늘의 위치 사진 | 당일 촬영한 GPS 포함 JPEG 1건 |
| 주간 | 주간 위치 기록 | 서로 다른 KST 날짜 2일에 유효 사진 제출 |
| 주간 | 주간 탐험 | 해당 주에 유효한 장소 인증 실적 누적 |
| 일일·주간 | 기타 생활 미션 | 자기 확인, 서비스 체크인과 서버 집계로 판정하는 확정 템플릿 |

**기상 미션의 기술적 의미:** `Asia/Seoul` 기준 05:00 이상 09:00 미만에 사용자가 명시적으로 실행한 서비스 체크인을 오전 기상 체크인으로 분류합니다. 실제 잠에서 깨어난 시각은 검증하지 않고 사용자별 시간 변경과 지각 인정은 제공하지 않습니다.

### 6.2 사진 EXIF 기반 인증 구상

1. 사용자가 촬영한 사진을 웹사이트에 업로드한다.
2. Spring Boot 서버가 이미지에서 **GPS 위치와 촬영 시각**을 추출한다.
3. 해당 퀘스트의 위치·날짜·중복 제출 조건을 검사한다.
4. 유효한 인증에 한해 퀘스트 완료 및 보상을 반영한다.

**확정된 실패 정책:** **GPS 정보가 없는 사진은 예외 없이 위치 인증 실패**로 처리한다. 메타데이터가 없는 사진에 대한 대체 인증, 별도 보상이나 예외 인정 정책의 개발은 **프로젝트 이후 과제**로 둔다. MVP에는 유효하지 않은 제출을 거절하는 기본 처리만 둔다. 다른 종류의 퀘스트를 수행할 수 있다는 점과, 해당 사진의 인증을 예외적으로 승인한다는 점은 구분한다.

**중요한 한계:** GPS와 촬영 시각은 삭제·변조가 가능하다. MVP는 GPS 존재·좌표 범위와 촬영 시각의 배정 기간 포함 여부만 확인하며 실외 촬영, 현재 위치, 특정 장소·반경, 사진 간 거리와 실제 이동을 증명하지 않는다.

**기술 검증:** Android Chrome에서 촬영한 JPEG 파일을 브라우저로 업로드했을 때 EXIF GPS·촬영 시각이 유지되고 서버가 이를 추출하는지 확인한다. iOS Safari는 MVP 검증 대상에서 제외한다. 최대 10 MiB의 JPEG만 지원하고 HEIC·HEIF는 명확한 오류로 거절한다.

**개인정보 보호:** 원본 GPS 좌표를 다른 사용자나 그룹 랭킹에 공개하지 않는다. 실패 파일·좌표는 판정 후 24시간 이내, 성공 파일·좌표는 시즌 종료 후 30일에 삭제한다.

## 7. 기술적 목표 및 필수 기능 연결

| 기술·요건 | 서비스에서의 구현 목적 |
|---|---|

| 외부 서버 요청 | 구글·네이버 OAuth 인가 코드 교환과 사용자 정보 조회 |

| 동시성 제어 | 같은 그룹에 동시 보상 지급 시 경험치 누락 방지, 퀘스트 중복 보상 방지 |
| PG 테스트 결제 | 아바타 꾸미기 아이템 구매 |

| 관리자 대시보드 | 회원·그룹·퀘스트·랭킹·결제/환불 현황 |

**구현 원칙:** 퀘스트 판정, 보상 지급, 사용 여부와 환불 가능 여부는 서버를 기준으로 처리한다. WebSocket은 서버에서 확정한 결과를 전파하는 데 이용한다. 개인 기여도와 그룹 점수도 서버의 확정 기록에서 집계한다.

## 8. 아이템·결제·환불 및 수익 모델

### 8.1 이번 프로젝트에서 구현할 과금

- **판매 대상:** 사용자 **아바타 꾸미기 아이템**.
- **비과금 대상:** **크리처의 기본 육성·성장 과정**. 현 단계에서는 과금 기능과 연결하지 않는다.
- **결제 방식:** PG 연동 **테스트 결제**.
- **환불 기준:** **구매 아이템이 미사용이면 환불 가능, 사용한 아이템은 환불 불가**를 기본 정책으로 한다.
- **필요한 상태 관리:** 결제 성공 여부, 아이템 보유 여부, 사용 여부, 환불 요청 및 결과.

**사용 시점:** 꾸미기 아이템은 아바타에 최초 장착한 순간 사용으로 확정합니다. 단순 구매만으로 사용 처리하지 않으며 장착을 해제해도 미사용 상태로 돌아가지 않습니다.

### 8.2 향후 검토

광고 시청 보상, 광고 제거, 편의성 아이템 등은 팀원이 제안한 확장 가능성으로 남긴다. **실제 광고 연동이나 유료 성장 버프는 이번 2주 MVP 범위에 포함하지 않는다.**

## 9. 개발 범위 및 2주 추진 방향

**MVP 필수 범위:** 계정 인증, 전체 가입자 대상 그룹 참여, 그룹 크리처 육성, 사용자 아바타, 일일·주간 퀘스트, 보상·기여도, **그룹 내 개인 랭킹·그룹 간 랭킹**, WebSocket 상태 갱신, 동시성 방지, 아바타 꾸미기 아이템 테스트 결제·환불, 관리자 대시보드, 다크 모드.

**기술 검증 범위:** 사진 EXIF 기반 위치 인증 퀘스트는 핵심 기능이므로 Android Chrome의 촬영·업로드·서버 판정 흐름을 MVP 완료 전에 통과해야 한다.

**프로젝트 이후 과제:** GPS 없는 사진의 대체 인증·예외 인정 정책, 복잡한 부정행위 탐지, 광고 시스템, 모바일 네이티브 연동, 정밀 GPS 경로 추적, 복잡한 소셜 기능.

| 단계 | 중점 목표 |
|---|---|
| 1~2일차 | 크리처/아바타 역할·그룹 참여·랭킹 규칙 확정, 화면·데이터 초안, EXIF 기술 검증 |
| 3~5일차 | 계정·그룹·육성·아바타·일일 퀘스트 기본 구현 |
| 6~9일차 | 일일·주간 퀘스트, WebSocket, 랭킹·동시성, 테스트 결제·환불 병렬 개발 |
| 10~12일차 | 사진 인증 가능 범위 반영, 관리자 기능, 통합 테스트 |
| 13~14일차 | 경합/중복 요청·결제·환불 시나리오 테스트, 시연 및 발표 준비 |

**4인 역할 분담 예시:** ① 계정·그룹 ② 크리처·퀘스트·동시성 ③ 프론트엔드·아바타·실시간 경험 ④ 결제·환불·관리자. 그룹·개인 랭킹의 데이터 산출은 크리처·퀘스트와 연계해 분담한다. 최종 분담은 팀원 합의로 결정한다.

## 10. 성과 확인 지표

- 전체 가입자 중 퀘스트 참여 사용자 비율
- 그룹당 주간 참여 사용자 수와 퀘스트 완료 수
- 개인 기여도 및 그룹 간 점수 집계의 정확성
- 크리처 성장·진화 단계별 도달 현황
- 동시 완료·중복 제출 시 보상 데이터 정합성
- 위치 메타데이터가 유효한 사진의 인증 성공 여부
- 테스트 결제·아이템 사용·환불 조건 분기 처리 성공 여부

> 위 지표는 구현 상태와 참여 현황을 확인하기 위한 것이며, 사회적 고립이나 신체 활동의 개선 효과를 입증한 것은 아니다.

## 12. 발표·면접용 소개문

> 저희는 일상의 작은 활동을 지속할 계기가 부족하거나, 낯선 사람과의 적극적인 교류가 부담스러운 사람에게 게임을 통한 참여 동기를 제공하고자 했습니다. 서비스에 가입한 사용자들은 그룹에 참여하여 일일·주간 퀘스트를 수행하고, 하나의 공동 크리처를 성장시키며 그룹 내 개인 기여도와 그룹 간 성과로 경쟁합니다. 기상 체크인과 GPS 메타데이터를 이용한 야외 사진 인증 등 현실 활동에 연결되는 퀘스트도 제공하고자 합니다.
>
> 기술적으로는 Spring Boot와 MySQL을 기반으로 퀘스트 및 성장 상태를 관리하고, WebSocket으로 결과를 실시간 공유합니다. 여러 사용자가 동시에 보상을 받는 상황에서 데이터 정합성을 보장하고, 크리처 성장과 분리된 아바타 꾸미기 아이템에 PG 테스트 결제·사용 여부 기반 환불을 구현하여 웹 서비스의 핵심 기능을 경험하는 것이 목표입니다.
